# Agent benchmark: 182-spring

Does myceliums change the outcome of a coding agent's work, not just its tool use? Generated by `python3 evals/agent/agent_eval.py report 182-spring` from `results.jsonl`, `meta.json` and `tasks_snapshot.json` in this directory; method in [`../../README.md`](../../README.md).

## Setup

- **Date:** 2026-11-23
- **Agent:** Claude Code 2.1.330, `--model sonnet` (resolved: `claude-sonnet-5-5`), `--effort medium`, `--max-turns 100`, timeout 1200 s per session
- **myceliums:** `myc 0.3.2` built from commit `388c6e1291fd` (binary sha256 `a42bffce8d3aec06…`); 9 MCP tools offered
- **Tasks:** 30 from `tasks/tasks-java.json` over 1 pinned repositories, 3 repetition(s) per task and condition, 270 graded sessions.
  - `spring-framework` v7.1.0 (`f2e4863de60e`, Java): index 145,670 symbols in 10,158 files
- **Same in every condition:** prompt, model, effort, turn limit, timeout; built-in tools `Read`, `Grep`, `Glob`, `Bash` (+ `ToolSearch`); `--setting-sources project` (the working copy's `.claude/settings.json` and `CLAUDE.md` load, the user's do not); fresh working copy and index copy per session; transcripts checked for the expected tools, MCP server and subagents.
- **Grading:** set-based precision / recall / F1 against gold sets derived with compiler tooling; success = F1 ≥ 0.8.
- **Statistics:** repetitions averaged within each task; 95 % percentile bootstrap intervals over tasks (10,000 resamples), every pair of conditions compared, none of them a baseline (see *Pairwise comparisons*).

| Condition | What the session has |
|---|---|
| **none** | no myceliums at all: no MCP server, no CLAUDE.md routing block, no hooks; the built-in read and search tools only |
| **C** | the myceliums MCP server (default core toolset, 9 tools loaded up front) + what `myc setup-claude --scope project --no-agent` writes: the routing block in CLAUDE.md, the SessionStart (context line), PostToolUse and PreToolUse grep-redirect hooks in .claude/settings.json |
| **D** | myceliums only (#178): the MCP server and `Read`; `Grep` and `Glob` denied; Bash, if offered, limited by a PreToolUse hook to an allowlist (`myc`, plain file operations, git without search, the task's own build/test commands); edit tools on edit tasks |

## Notes

- Pre-registered in commit 7b2b2d1 (pushed before the first session); calibration sessions are not pooled. Primary outcome: tokens and cost per solved task. Success and F1 are a harm check: arm A was at the ceiling, so the run cannot show a success gain, and a true loss below about 25-29 points would likely be missed. No significant difference is not evidence of equal success.
- Reading: no difference between C (myc + grep) and A was detected in pooled tokens or cost per solved task (the agent used myc in 13 of 90 C sessions, all deep transitive); D (myc only) cost about 2.3x and used about 2.7x the tokens of A per solved task. Post hoc by category (6 tasks each): D used more tokens than A everywhere except deep transitive (0.73x, interval includes 1). Full reading, verdict and limits: README, Result of the main run (#182).
- Limits: gold agent-labelled, not human-checked; Spring is very likely in the training data (five sessions, C 3 and D 2, answered one concept task exactly without any tool call; SUPPLEMENT.md counts unseen items); 12 comparisons, only McNemar corrected; cost per session and cache writes fell over the run; known myc gaps #186, #187, #188, #194.
- Index: 145,670 of 145,670 symbols embedded in 17,699 s (other jobs running; 98,952 s user CPU, 6.9 GB peak memory, 1.2 GB on disk); fingerprint sha256 fc3c476d228fc2d39c87cb840f73187297919761a03acf742b3dff80033e3a0f (sorted relative path + file sha256, 3,902 files).
- Run 2026-11-23 20:27-22:01 UTC, one session at a time, no retries. Wall times are comparable between the arms only because the schedule interleaves them (load 12-91, median 31, from other jobs). Outside/network audit of all 270 transcripts: outside_audit.json; no session read a gold file or a later Spring version.
