# Agent benchmark: 2026-11-20-variants

Which integration layer makes a coding agent use myceliums, and does it help? Generated by `python3 evals/agent/agent_eval.py report 2026-11-20-variants` from `results.jsonl`, `meta.json` and `tasks_snapshot.json` in this directory; method in [`../../README.md`](../../README.md).

## Setup

- **Date:** 2026-11-20
- **Agent:** Claude Code 2.1.329, `--model sonnet` (resolved: `claude-sonnet-5-5`), `--effort medium`, `--max-turns 40`, timeout 900 s per session
- **myceliums:** `myc 0.3.2` built from commit `6661198e1ad3` (binary sha256 `c911169eb3c7259c…`); 9 MCP tools offered
- **Tasks:** 20 from `tasks/tasks-hard.json` over 3 pinned repositories, 2 repetition(s) per task and condition, 116 graded sessions.
  - `fastapi` 0.162.5 (`5add7a458d62`, Python): index 7,370 symbols in 1,066 files
  - `fzf` v0.75.0 (`c7bf2b8eea25`, Go): index 2,865 symbols in 112 files
  - `hono` v4.13.18 (`f6fbaf0299c4`, TypeScript): index 10,588 symbols in 447 files
- **Same in every condition:** prompt, model, effort, turn limit, timeout; built-in tools `Read`, `Grep`, `Glob` (+ `ToolSearch`); `--setting-sources project` (the working copy's `.claude/settings.json` and `CLAUDE.md` load, the user's do not); fresh working copy and index copy per session; transcripts checked for the expected tools, MCP server and subagents.
- **Grading:** set-based precision / recall / F1 against gold sets derived with compiler tooling; success = F1 ≥ 0.8.
- **Statistics:** repetitions averaged within each task; 95 % percentile bootstrap intervals over tasks (10,000 resamples), paired with condition `A` for the differences.

| Condition | What the session has |
|---|---|
| **A** | the myceliums MCP server only (default core toolset, 9 tools loaded up front) |
| **C** | A + what `myc setup-claude --scope project --no-agent` writes: the routing block in CLAUDE.md, the SessionStart, PostToolUse and PreToolUse grep-redirect hooks in .claude/settings.json |
| **E** | C + the `code-explorer` subagent (`myc setup-claude --scope project`) and the Agent tool, with Claude Code's built-in subagents denied |

## Notes

- Task set: tasks/tasks-hard.json (v2). The first hard set (tasks/tasks-hard-v1.json) was calibrated with 10 sessions without myceliums (results/2026-11-20-calibration): all 10 scored F1 = 1.00, so it was at the ceiling. v2 asks the same question types one to two levels deeper or wider; with the calibration allowance spent, v2 was not calibrated before the matrix. Its A results (success 98 %, see above) show it is near the ceiling as well.
- Sessions: 10 calibration (condition none) + 123 matrix launches = 133 Sonnet sessions; 3 more ran against a local mock API (agent_eval.py probe, no model call). Of the 123 matrix launches, 116 are graded; 7 were cut off without a result and are counted as retries: 3 when the benchmark machine went to sleep during the run, 4 when the run was stopped externally (twice hono-amb-ctx-header-d2__E__r2, once fastapi-flow-openapi-lenient__C__r2 and hono-tests-trydecode__C__r2). To stay near the budget of 120, 4 planned sessions were not run: hono-amb-ctx-header-d2 C and E, hono-tests-trydecode C and E, all repetition 2. Every task has at least one repetition in every condition; per-task means use the repetitions that ran.
- All conditions ran the same model (claude-sonnet-5-5 via --model sonnet), effort, prompt, --max-turns 40 and 900 s timeout; one session per repository at a time, three repositories in parallel. Wall times include heavy, varying load from unrelated work on the machine (load average 50-290).
- What the agent saw, checked with agent_eval.py probe against a mock API (Claude Code 2.1.329): the 9 core tools are sent with full schemas in A, C and E (none deferred; ToolSearch not needed); the project CLAUDE.md with the routing block reaches the context in C and E, ~/.claude/CLAUDE.md in no condition; the grep hook's hint reaches the context; the SessionStart hook's output is a systemMessage, shown to the user and not to the model; in E the Agent tool offers code-explorer only and the subagent gets the myceliums tools and Read.
- The sessions have no shell (as in the pilot), so the CLI commands that the routing block and the grep hook name (myc callers X, myc impact X) cannot be run; the routing block also names the MCP tools, which the agent used.
- In C and E the working copy holds the files myc setup-claude writes (CLAUDE.md, .claude/, .mcp.json) after the index was built, as in the documented order (myc analyze, then myc setup-claude). They are uncommitted and newer than the index, so the MCP analyze tool's freshness check calls the index stale and re-indexes: it timed out after 300 s in hono-amb-ctx-header-d2__C__r1 and re-indexed without embeddings in hono-blast-createresponse-d3__E__r1. In A, analyze calls were cache hits. The SessionStart hook, which uses the commit-based cache check, reported the same index as ready.
