# Agent benchmark: 2026-11-21-outcome

Does myceliums change the outcome of a coding agent's work, not just its tool use? Generated by `python3 evals/agent/agent_eval.py report 2026-11-21-outcome` from `results.jsonl`, `meta.json` and `tasks_snapshot.json` in this directory; method in [`../../README.md`](../../README.md).

## Setup

- **Date:** 2026-11-21
- **Agent:** Claude Code 2.1.330, `--model sonnet` (resolved: `claude-sonnet-5-5`), `--effort medium`, `--max-turns 4`, timeout 420 s per session; the prompt states the turn limit (the same text in every condition)
- **myceliums:** `myc 0.3.2` built from commit `951d041ff9e0` (binary sha256 `4ef9e803790e41b4…`); 9 MCP tools offered
- **Tasks:** 11 from `tasks/tasks-outcome.json` over 1 pinned repositories, 1 repetition(s) per task and condition, 22 graded sessions.
  - `django` 5.1.4 (`2d4add11fd57`, Python): index 12,443 symbols in 828 files
- **Same in every condition:** prompt, model, effort, turn limit, timeout; built-in tools `Read`, `Grep`, `Glob` (+ `ToolSearch`); `--setting-sources project` (the working copy's `.claude/settings.json` and `CLAUDE.md` load, the user's do not); fresh working copy and index copy per session; transcripts checked for the expected tools, MCP server and subagents.
- **Grading:** set-based precision / recall / F1 against gold sets derived with compiler tooling; success = F1 ≥ 0.8.
- **Statistics:** repetitions averaged within each task; 95 % percentile bootstrap intervals over tasks (10,000 resamples), paired with condition `none` for the differences.

| Condition | What the session has |
|---|---|
| **none** | no myceliums at all: no MCP server, no CLAUDE.md routing block, no hooks; the built-in read and search tools only |
| **C** | the myceliums MCP server (default core toolset, 9 tools loaded up front) + what `myc setup-claude --scope project --no-agent` writes: the routing block in CLAUDE.md, the SessionStart (context line), PostToolUse and PreToolUse grep-redirect hooks in .claude/settings.json |

## Notes

- Pilot: one repetition, 11 paired tasks (n = 11). The 95 % intervals are wide; read the differences as direction and rough size, not as a precise estimate.
- Budget: --max-turns 4, i.e. at most three rounds of tool calls before the final answer (parallel calls in one reply share a round; checked with probe against the mock API). The prompt states this in both conditions. Every failed none session reached the limit with a fourth round of tool calls and so ended without an answer (status max_turns, F1 = 0); no session in either condition ended with a wrong answer below the threshold.
- Calibration (10 sessions, condition none, the same prompt): 5 of 6 tasks succeeded at --max-turns 8 (results/2026-11-21-outcome-calibration, at the ceiling; that prompt still said parallel calls count one turn each, which the probe disproved), 1 of 4 at --max-turns 4 (results/2026-11-21-outcome-calibration-t4). The main run uses 4.
- Session accounting: 23 of the 24 approved sessions launched, 22 graded. django-amb-transaction-get-connection (C) was killed with its run chunk by an external stop after its first tool call and was run again; django-tc-resolve-url was therefore not run in either condition, because its pair would have exceeded the budget.
- Index: the django/ package (12,443 symbols, all 12,443 embedded with the default jina-embeddings-v2-base-code, template 2, chunking), built once with myc analyze --strict-embeddings (1,447 s, 1,324 s of it embedding) and copied fresh for every C session. The probe showed the SessionStart hook reporting it ready (index commit = HEAD), so no session re-indexed.
- The gold sets follow static call rules (calls by name, self/cls/super() through the enclosing class and its bases, instantiation by name) that the question spells out. A call graph computes exactly this by construction, while an agent with grep has to emulate it; the tasks were chosen by graph properties (depth, files, same-named functions) before any myceliums output was seen, but they are structural questions of the kind myceliums is built for.
