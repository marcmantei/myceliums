# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html). Entries before
0.3.2 were reconstructed from git history; numbers in parentheses are issues or
pull requests.

## [Unreleased]

### Breaking
- **`find_callers` and `find_callees` answer in compact text; `impact_of_change` and `trace_flow` list hits grouped by file (#181).** A tool result stays in the agent's context and is re-sent with every later call, so the navigation tools now give one line per hit, `qualified_name kind :start-end`, under a heading line with its file (each file once), plus `[depth N via X]` past depth 1, `(resolved: …)` on name-matched edges, and the `Incomplete`/`Next` block. `find_callers`/`find_callees` no longer return `structuredContent` or an output schema; `detail: "full"` returns the previous JSON (`CallersOutput`/`CalleesOutput`) as text, now with each hit's `signature`. A file heading plus a qualified name is a handle every symbol parameter accepts, so `explain_symbol` shows any hit in full. `impact_of_change` (symbol and file mode) drops the *Files with dependents* section, which repeated the file headings, and pages over dependents; `trace_flow` marks the symbols on chains `[chain N, call K]`. Measured with the new `agent_eval.py replay` (`evals/agent/aeval/replay.py`; report: `evals/agent/results/2026-11-23-compact-output/REPLAY.md`), which replays the 265 myceliums calls of the #163/#171 sessions against two builds on the same Django and Vue indexes: 1,104,910 → 505,145 characters (274,810 → 136,478 tokens in `o200k_base`, an OpenAI tokenizer used for the ratio, not Claude's); `find_callers` 956,541 → 418,522, `find_callees` 78,335 → 33,043, `impact_of_change` 29,185 → 20,205, `trace_flow` 40,849 → 33,375. For every call of all four tools both builds give the same hits (file, qualified name, start line, depth or chain position, `via`, edge marks), totals, `Incomplete` reasons and `Next` step, and error results are the same text; the replay checks this. The deprecated `get_callers`/`get_callees` keep their structured output. `myc format-hook` reads both forms.
- **Smaller tool definitions (#181).** The core tools' descriptions say what each answers and when to use it; how to read results moved into the server instructions, which are stated once per request instead of once per tool (Claude Code re-sends them, like the tool definitions, in every request prefix). Input schemas of every tool lose `$schema`, `title`, `format`, `minimum: 0` and the `null` an optional field added to `type` and `enum`; the core tools' `repo_id` and `offset` carry no description. What the model receives for the default profile (name, description and input schema of the nine core tools) went from 11,847 to 6,697 characters (2,807 → 1,592 tokens in `o200k_base`, not Claude's tokenizer; #178 measured the old definitions at about 5.4k Claude tokens); the server instructions grew from 1,548 to 1,778 characters. The `tools/list` JSON of the core profile went from 19,264 to 9,920 characters. A test (`tools_list_snapshot`) fails when the core definitions or the instructions grow more than 10 % past these sizes. The tool set, names and parameters are unchanged apart from the new `detail`.
- **`find_callers` drops `unlinked_call_sites`; `find_callers` and `find_callees` gain `incomplete` (#169).** The note on unlinked call sites moved into `incomplete.reasons`, next to the depth limit and the page, with `branches_cut` and `next` (the exact call that continues). `depth_limited` is now true only when the depth limit left symbols out (it was true whenever a hit sat at the last depth). Library API: `myceliums_core::navigation::call_chains` returns `Result<CallChains, NoChain>` instead of `Option`, `CallChains` gains `longer`, and `RepoInfo` gains `call_record_version`.
- **Upgrading: every index is re-analyzed once (#169).** The registry records a call record version (`myceliums_storage::schema::CALL_RECORD_VERSION`); an index built before every caller's unlinked calls were recorded has version 0, and the cache check of `myc analyze`, the MCP `analyze` tool and the SessionStart hook re-analyze it instead of reusing it, as for the #146 classification. Until then, a walk over such an index says that the calls it cannot follow are unknown.
- **The default embedding model is `jina-embeddings-v2-base-code`, with embedding-text template 2 and chunking on (#157).** Eleven model × template × chunking variants were scored on the 168-query real-repository set. Jina with template 2 was the only one whose gain over `multilingual-e5-small` held on the held-out queries: +0.070 [+0.010, +0.128] (mean of semantic and hybrid nDCG@10). On the golden set it raises nDCG@10 by +0.114 [+0.035, +0.196] in semantic and +0.086 [+0.024, +0.150] in hybrid search; the golden baseline was re-recorded for it. The price is indexing time. A first index takes about 4.4× as long as with e5-small (release build, 4 vCPU). The vectors take twice the space (768 dimensions), a query takes about 35 ms instead of 12 ms, and the download is 644 MB. That is over the index-time limit fixed before measuring (2.5×): **the index-time budget was waived by owner decision — 4.4× first index; incremental runs reuse vectors.** The protocol by itself kept e5-small, and jina was chosen after the held-out results were known. Protocol, all tables and limits: `crates/myceliums-benchmarks/benchmarks/METHODOLOGY.md`. Before a first index, `myc analyze` now says that it takes the longest, gives the download size when the model is not cached, and names the fast option. The MCP `analyze` tool answers once the graph is built and embeds in the background (see Added). The fast option is `model = "multilingual-e5-small"` with `chunking = false`: multilingual queries and a 4.4× faster first index. **Upgrading:** every existing index is re-embedded once, on its next `myc analyze` or MCP `analyze` (which re-analyzes an index whose recorded embedder differs from the configured one); after that, runs reuse vectors again. If `.myceliums.toml` names no model, the project moves to jina. If it names `model = "multilingual-e5-small"` (earlier `myc init` versions wrote it), it stays on e5-small with template 2 and chunking. Add `chunking = false` to keep the previous configuration exactly and skip the re-embed.
- **`myc mcp` now exposes the core toolset by default: 9 tools instead of 55** (#97). `search_code`, `explain_symbol`, `find_callers`, `find_callees`, `impact_of_change`, `trace_flow`, `find_dead_code`, `list_repos` and `analyze` are named after the questions agents ask and carry `_meta["anthropic/alwaysLoad"]`, so Claude Code loads them up front instead of deferring them behind tool search (the #99 pilot: 0 of 90 sessions called a myceliums tool). The other tools are opt-in by group — `graph`, `review`, `architecture`, `knowledge`, `email`, `cross_repo`, `admin` — with `myc mcp --toolsets core,architecture,...` or `myc configure --set mcp.toolsets=...`; `--toolsets all` restores every tool. Clients that call a non-core tool by name must add its group.
- Duplicate tools are merged; the old names stay as deprecated aliases in the `deprecated` group (part of `all`) for one release, each description naming its replacement: `context_search`, `search_documents` (which was `context_search` under another name, not a BM25 document search), `semantic_search`, `hybrid_search` → `search_code` with `mode`; `symbol_context`, `get_symbol_definition` → `explain_symbol`; `get_callers`, `get_callees` → `find_callers`, `find_callees`; `detect_impact` → `impact_of_change`; `get_graph_diff`, `snapshot_diff` → `detect_architecture_drift` (#97).
- **Upgrading:** the old tool names are not in the default profile. A client that still calls `context_search`, `symbol_context`, `get_callers`, `detect_impact`, ... gets "tool not found" until it moves to the new names; to keep the old names for this release, run `myc configure --set mcp.toolsets=deprecated` (or `myc mcp --toolsets core,deprecated`) (#97).
- Without `repo_id`, tools no longer fall back to the most recently analyzed repository: they use the indexed repository containing the working directory (the deepest, matched on whole path components — `/x/app-two` is not inside `/x/app`) and otherwise fail with `No index covers <dir>` and a `Next:` step. Every `Index:` line names its repository (`Index: my-app, commit …`). Overloads in one file are ambiguous, as in `myc callers`, and are picked with `file_path:qualified_name:line` (#97).
- Text tools return their answer as plain text content; it is no longer wrapped as `{"text": "..."}` JSON and duplicated in `structuredContent`, and these tools have no `outputSchema`. Tools with a natural record or list shape (`find_callers`, `find_callees`, `find_dead_code`, `list_repos`, `get_stats`, `get_file_symbols`, `get_communities`, `get_community_detail`) return typed `structuredContent` with an output schema. `list_repos` is now structured. The `TextOutput` type is gone from the `myceliums-mcp` crate, and `run_mcp_server`/`run_mcp_http_server` take the `Toolsets` to serve (#97).

- **Library API: `myceliums-storage` and `myceliums-core` return typed errors instead of `anyhow::Error`** (#101). Storage functions return `myceliums_storage::StorageError` (`NoIndex`, `RepoId`, `Database`, `Arrow`, `Io`, `Json`, `InvalidData`); core functions return `myceliums_core::MyceliumError`, which gains `Store(StorageError)` (a repo-id error from storage stays `Repo`), `ParseAborted`, `Cancelled` and `Json`, plus `parse_abort()` and `is_cancelled()` in place of `anyhow` downcasts; its `Storage(String)` ("no repository registered") is renamed `NotAnalyzed(String)` (#118). Code using `anyhow` keeps working through `?`. Unused dependencies are dropped: `anyhow`, `uuid`, `chrono`, `dirs` from storage, `tower-http` from http, `serde`, `tracing` from cypher.
- **Upgrading indexes built before embedding metadata was recorded** (#92, #118): an index with vectors but no recorded embedding model cannot be searched by meaning — `search_code` falls back to keyword search in `auto` mode and says so for `semantic`/`hybrid`. Such vectors predate the current embedding text and geometry anyway; run `myc analyze <path> --force` (or `analyze` with `force`) once to re-embed.

### Added
- **Dispatch: implementations inherit the callers of the methods they override (#190).** The analysis records an OVERRIDES edge from each method to every base-class, interface or trait method it overrides (transitively; static and private methods and constructors excluded; parameter counts must agree where both signatures give them; not for Go). CALLS edges are unchanged. `find_callers`, `impact_of_change` and `myc callers`/`impact` on an implementation list the callers of the methods it overrides; `find_callees` and `trace_flow` list the implementations of a called method (at most 8 per call in a list, the rest named in `Incomplete` with `explain_symbol` as the next step). Such hits are marked `dispatch via I.m, confidence c` (in `resolved` for `find_callers`/`find_callees`, `dispatch` in `myc callers --json`); the confidence falls with the number of implementations (0.9 for one, 0.2 beyond 16). Overrides of `toString`/`equals`/`hashCode` and the like are recorded as `universal` and never followed; `ambiguous` edges and `super.m()` calls do not dispatch. `explain_symbol` lists `Overrides` and `Implementations`, `find_dead_code` no longer lists implementations of called methods, and the diff mode of `impact_of_change` labels such dependents `dispatch caller`. On spring-framework v7.1.0 the share of dispatch targets reached goes from 0.21 to 0.64 on the dev set (dispatch case, 18 pairs; 33 of 34 added targets correct over all dev pairs) and from 0.27 to 0.97 on the held-out set (7 dispatch pairs, scored once; 21 of 29 added targets correct over all 60 pairs, 0.72 (0.54–0.85): four overrides beside the receiver's static type, four the labels leave out). CALLS precision and recall are unchanged there and on the fixtures, where dispatch adds 9 targets, all accepted by the gold. Cost on spring-framework (debug build, shared machine): 16,521 OVERRIDES edges, an override pass of 0.8 s, analysis 105–108 s against 92–104 s before. `graph-eval` reports dispatch per case and per language and takes `--held-out <name>`. Library API: `RelationshipKind::Overrides`, `myceliums_core::dispatch`, `Reached::dispatch`, `Walk::dispatch_cut`, `CallChains::dispatched`, `GraphHit::dispatch`. Numbers and limits: `docs/guides/call-resolution-limitations.md#dispatch-190`.
- C# and Kotlin classes record their base types; a Kotlin member call (`repo.save(x)`) is named by its method (it was `repo.save`, which matched nothing); in languages without call forms, a call matched by name to a method and its overrides links the overridden method (#190).
- **Java CALLS quality measured on spring-framework v7.1.0, with a dev set and a held-out set kept apart (#177).** All labels come from reading the code; none was taken from myceliums output.
  - **Held out** (`graph-gold/held-out/java-spring-heldout.json`): 60 call sites drawn at random (seed 4177) after the resolver changes below were frozen, and scored once. Recall 30/31 = 0.97 (0.84–0.99), precision 31/36 = 0.86 (0.71–0.94). All six errors are overloads with the same number of parameters (#186).
  - **Dev** (`java-spring-dev.json`, seed 177): 60 random sites plus 5 per hard Java case. **It is not held out:** the five Java binding fixes listed under Fixed came from reading its misses. An earlier draft of #177 reported it as held out (0.92 recall, 0.88 precision over all strata). Its random stratum scores 0.97 / 0.92 and its targeted strata 0.86 / 0.84.
  - `graph-eval` reports precision and recall per case and per stratum, and a "targets reached" share. Dispatch calls reach their interface method, but only 21–27% of the implementations they may run get an edge (#190).
  - Indexing the repository takes 30 s (release build, embeddings off) and peaks at 3.1 GB RSS.
  - Gaps filed: overload selection by argument types (#186), generics (#187), method references (#188).
- **Community detection has a budget and an off switch; analyze reports phase timings (#172).** `[community] time_budget_secs` (default 60, `0` = no limit) and `max_iterations` (default 100) bound the run; when either runs out, the best partition found so far is kept (every Leiden move only raises modularity) and the index records the communities as `partial` with the reason (`index_meta` key `communities`: state, reason, time, iterations, graph size, modularity). `analyze` (CLI and MCP) shows `Communities: N (partial)` and the reason; `get_communities` and `get_community_detail` gain `communities_notice`, `myc communities` and `get_community_metrics` print it. `myc analyze --skip-communities`, the MCP `analyze` parameter `skip_communities` and `[community] enabled = false` skip detection (recorded as `skipped`); search, callers/callees, impact and flows do not use communities. `myc analyze` and the MCP `analyze` summary end with `Phases: discover …, parse …, resolve …, communities …, processes …, embed …`, and the CLI's timing breakdown lists communities and processes. `[community] resolution` is now applied to the communities `analyze` stores (it was read but ignored). The tools that recompute communities on demand (`get_community_metrics`, the HTTP community metrics and graph views, wiki export, the architecture diagram, surprising connections) always use the defaults: a 60 s budget, 100 iterations, resolution 1.0; of these, only `get_community_metrics` reports a partial run. The recorded modularity is computed at resolution 1.0. Communities are deterministic for one index; a re-analysis of the same tree can differ slightly, because file nodes get new random UUIDs (Django with tests: 654 to 658 communities over three analyses). `cargo run --release -p myceliums-core --example community_bench` compares the new implementation with the `graphrs` one on an analyzed index.
- **Workspace packages and tsconfig `paths` resolve like relative imports (#169).** The analyzer reads `package.json` `workspaces`, `pnpm-workspace.yaml` and `lerna.json` (at any depth), each member's `name` and entry (`source`, `exports`, `module`, `main`, `types`; an entry under `dist/` stands for `src/`, then `src/index.*`), and `compilerOptions.paths`/`baseUrl` of `tsconfig*.json`/`jsconfig*.json` through `extends` (`myceliums_core::JsProject`). `import { isArray } from '@vue/shared'` in vuejs/core now binds `packages/shared/src/general.ts`; external packages stay external. On vuejs/core v3.5.46: CALLS edges between two packages 138 → 948, of which the TypeScript checker confirms 11 → 808; call sites into libraries 5,984 → 3,723. Editing a `package.json`, `pnpm-workspace.yaml`, `lerna.json`, `tsconfig*.json`, `jsconfig*.json` or a recorded `extends` base marks the index stale, and `myc analyze --watch` runs a full analysis when such a file (or `.myceliums.toml`) changes or is deleted, then re-reads `.myceliums.toml`. `exports` subpaths match as in Node (exact key, then the longest pattern prefix); a nearer tsconfig without `paths` does not inherit an ancestor's; two equally near packages of one name stay unresolved unless one is an example or fixture; paths above the repository root and symlinks are never followed. A new graph-eval gold set, `typescript-monorepo` (`tests/fixtures/graph-accuracy/ts-monorepo/`, 25 edges, cross-checked with the TypeScript compiler), goes from recall 0.32 to 1.00 at precision 1.00; the other sets and the held-out set are unchanged, and the baseline is re-recorded for the new set. Numbers and rules: `docs/guides/call-resolution-limitations.md`.
- **Graph walks that stop early say so (#169).** `trace_flow`, `find_callers`/`find_callees` with a depth, `impact_of_change` and `myc callers`/`callees`/`impact` name every cut in an `Incomplete (N branch(es) not followed)` block right under the first line (structured: `incomplete`): the depth limit and how many symbols one more step adds, chains longer than the listed window, the page, calls made on the walk that got no CALLS edge (through a callback, more than two candidates, an unbound project name; with file and line), and unlinked call sites named like a walked symbol — each with the exact next call. The analysis records each caller's unlinked calls for this (`CallResolutionStats::unlinked_by_caller`; library calls are not recorded); an incremental re-index drops the changed files' entries — also from the per-name counts, now derived from the per-caller record — and the walks, callers and callees side alike, say those calls are unknown until the next full analysis. Every `Next` names the repository. The #163 sessions lost at 10 and 40 turns had answered from one partial `trace_flow` result that did not say it was partial.
- **Embedding stack measured end to end (#157).** Local embedding models run in-process on ONNX Runtime (through `ort`, `tokenizers` and `hf-hub`, the crates and versions fastembed already locked — no new crates in the dependency tree; the reranker stays on fastembed). Every registry model is pinned to a HuggingFace commit and its weights to a SHA-256, checked after download (size on every load); graphs with external weights load. Texts are sorted by token count and batched up to a token budget (`[analysis] embedding_batch_tokens`, default 16,384) instead of 256 random texts padded to the longest — on the hosted runner `multilingual-e5-small` (template 1) indexed the four evaluation repositories in 535 s instead of 1,750 s (debug builds of the evaluator, runs 44884767742 and 44434858317), and in about 220 s in a release build. `MYCELIUMS_EMBEDDING_THREADS` caps the session's CPU threads; `myc analyze` and the MCP `analyze` tool show embedding progress.
- Embedding-text template 2 (#157): language, kind and `file::qualified.name`, the name split into words, decorators and signature, the doc comment or docstring, then the body without the signature line and docstring it repeats, lines trimmed. Doc comments directly above a symbol (`///`, `/** */`, `//`, `#` lines) are extracted at parse time into `SymbolMetadata.doc`; BM25 does not read them. Template 2 is the default: chunking (on by default) needs it, and the models evaluated in #157 were measured with it. Template 1 stays for the e5 family with `chunking = false` (the fast option) and for remote models.
- Chunking of long symbols (#157, `[embedding] chunking`, on by default; `false` turns it off): the header chunk plus overlapping 512-token body chunks counted in the model's own tokens (64 tokens overlap, at most 16 vectors per symbol; classes, interfaces, enums and modules are not chunked), stored in a `chunks` table keyed to the symbol. `Store::vector_search` scores a symbol by its best vector and returns one row per symbol, exactly (`chunked_search_is_the_brute_force_top_k`). Vector reuse (#151) carries chunk vectors over a re-index and reuses unchanged body chunks of changed symbols by text hash. Measured: +0.026 to +0.050 on the 60 real-repository queries whose answers include a long symbol for four of five models (+0.033 [+0.003, +0.066] for `multilingual-e5-small`), no measurable change over all queries.
- Registry entries `granite-embedding-small-english-r2`, `coderankembed` and `gte-modernbert-base`; the README's model table lists measured quality, index time, query latency, memory, download size and license for every evaluated model.
- Embedding-variant evaluation (#157): `real-repo-eval --model/--template/--chunking/--modes/--no-demotion/--repos` records indexing time, texts, chunk vectors, vector and disk bytes, semantic query latency, peak memory, download size and license, and scores a long-symbol slice; `real-repo-compare` turns variant reports into quality, cost and budget tables, the dev selection and its held-out confirmation; the `Retrieval Quality (real repositories)` workflow takes a `variants` matrix (and `release` for cost measurements with the incumbent re-measured on every runner).
- **The MCP `analyze` tool embeds in the background (#157).** It builds the graph without running the model (`Analyzer::defer_embeddings`: unchanged symbols still take their vectors over from the previous index), swaps the index in and answers; the other symbols are then embedded on a blocking-pool thread (`myceliums_core::embed_pending`). A first index with the default model — a 644 MB download and minutes of inference — therefore never runs inside one tool call, which clients abandon after a few minutes. The job writes no table the graph is read from until it is done: it stages each symbol's vector as chunk row 0 next to its body chunks, every 1,024 symbols or 20 s, where vector search already finds it, and keeps the accounting in the index metadata; both tables are left out of the graph cache's fingerprint, so cached graphs stay and running calls do not fail with "the index was replaced". At the end it moves the staged vectors onto the symbols' rows in one write and compacts the tables; `search_code` and `impact_of_change` retry once if that write lands mid-call. The job holds the repository's analysis lock; the Index line of every result (with the model download's progress and an estimate of the time left), the search warnings and `server_stats` show its progress; `auto` search uses keywords until the first vectors are stored. It stops between two model batches — or between two reads of the model download — when the server stops serving (stdin closed, Ctrl-C), and the process waits for it at most 5 s; an `analyze` that re-analyzes the repository (another embedder, a moved HEAD, `force`) stops it first. A stopped or failed job keeps what it stored and the next `analyze` of the fresh index resumes it; a job that panics ends as failed instead of staying "running". A cached index whose recorded embedder (model, template, chunking) differs from the configured one, or that has no embeddings yet, is re-analyzed instead of reported as cached; a partially embedded index says "call analyze to embed the rest".
- Every file a local model loads is pinned (#157): `tokenizer.json`, `tokenizer_config.json`, `config.json` and `special_tokens_map.json` join the weights with a pinned size and SHA-256, checked like the weights; a file the revision lacks is pinned as absent and never fetched. `HF_ENDPOINT` must be an `https://` URL.
- Agent benchmark outcome eval (#153): 12 multi-hop tasks over Django 5.1.4 (transitive callers three levels up, blast radius over 16 to 24 files, callers of one of several same-named functions) with gold sets from an import-aware AST call graph (`py_edges.py --local-imports --star-imports`, `outcome_tasks.py`, audited against every AST call site), `run --prompt-budget` (the turn limit stated in the prompt) and `fetch --repo`. Result (pilot, 22 sessions on 11 tasks, Claude Code 2.1.330, three rounds of tool calls per session): success 36 % without myceliums, 100 % with what `myc setup-claude --no-agent` installs (+64 pp [+36, +91]), cost 0.65× [0.54×, 0.76×], input tokens not measurably different; every failure without myceliums ran out of turns (exact sign test over the 7 discordant tasks: p = 0.016). The budget was chosen in calibration because the agent without myceliums failed at it; with up to seven rounds (and an earlier, partly wrong budget text) it solved 5 of 6 of these tasks, so the gain shown is a budget effect, and cost and time without a budget were not measured.
- Agent benchmark outcome eval at scale (#163): 30 tasks over Django 5.1.4 and Vue 3.5.46 (`vuejs/core`, pinned in `repos.json`), six types including test coverage and four questions that are not about calls, gold sets from Python's `ast` module and the TypeScript 6.0 checker (`groundtruth/scale_tasks.py`, `vue_edges.js`, `vue_config.js`, `vue_hierarchy.js`), frozen after a 15-session calibration. `run --bash` adds the Bash tool in every condition and counts `myc` CLI runs as myceliums calls; `export-scale` merges per-budget runs and the report adds a budget curve, per-repository and per-type tables and an exact sign test. Measured (180 sessions, none vs `myc setup-claude --no-agent`, with Bash; primary analysis 27 tasks, without the three Django tests tasks the reused index cannot answer; intervals uncorrected): no success gain with 10 or 40 turns (85 % vs 81 %, 96 % vs 89 %, not significant) and wall time 0.69× and 0.84×; at 4 turns success +15 pp (not significant) and mean F1 +0.263 [+0.078, +0.452]. Results in `evals/agent/results/2026-11-22-scale/`.
- Agent benchmark variant matrix (#125): 20 harder multi-hop tasks (transitive callers, blast radius, same-named symbols, tests that reach a function, call chains) with gold sets from call graphs built by compiler tooling (`gotool edges`, `ts_edges.js`, `py_edges.py`, `hard_tasks.py`); conditions A (MCP server), C (+ `myc setup-claude --no-agent`) and E (+ `code-explorer` subagent); `agent_eval.py probe` checks a variant's setup against a local mock of the Messages API without calling a model. Result (116 sessions, Claude Code 2.1.329): the agent called myceliums in 80 % (A), 100 % (C) and 97 % (E) of sessions, never delegated to the subagent, and accuracy, tokens and cost did not differ measurably between the variants, all near the ceiling. An earlier, smaller version of the task set was at the ceiling without myceliums (10 of 10 calibration sessions).
- Unlinked calls are accounted for (#139): every analysis counts how many call sites got a CALLS edge and why the others did not (more than two candidates, a library target, a call through a variable, nothing in scope, outside any function); `myc analyze` and the MCP `analyze` tool print the counts, the index keeps them (`index_meta` key `call_resolution`), `find_callers` reports the unlinked call sites named like the symbol (`unlinked_call_sites`) and `impact_of_change` adds the same note for the changed symbols.
- A held-out real-repository CALLS set (#139): 52 call sites from flask, requests, gin and hono, drawn at random and traced by hand, scored by `graph-eval` next to the fixture gate when the pinned checkouts are present; reported, never gated.
- Per-call observability for the MCP server (#98): every tool call runs in one `tool_call` tracing span (tool, toolset, `repo_id`, `duration_ms`, `result_bytes`, `approx_tokens` = bytes/4, outcome `ok`/`is_error`/`protocol_error`/`cancelled`), applied once at the dispatch layer, and logs one line to stderr. `myc mcp` now logs at INFO for `myceliums_mcp` and WARN for `myceliums_core` without `RUST_LOG` (everything else stays at errors only; `RUST_LOG` overrides), writes colour codes only to a terminal, and takes `--log-format json` for one JSON object per line. Stdout stays the stdio transport.
- Local tool-call statistics (#98): the opt-in `server_stats` tool (toolset `admin`) and `myc mcp --stats-file <path>` report per-tool calls, `isError` results, protocol errors, p50/p95/max latency and result bytes. - **CALLS edges are resolved by scope, imports and declared types instead of a global name map** (#139). Measured: on the #94 fixture gold set call precision went from 0.57 to 1.00 and recall from 0.56 to 0.996 — but the rules were developed while reading those fixtures, so that is their coverage, not an estimate for unseen code; on a held-out sample of 52 call sites drawn at random from flask, requests, gin and hono and traced by hand (not reviewed yet), precision went from 0.48 to 0.95 and recall from 0.45 to 0.95, with wide intervals (22 pairs with a project target). Only Python, TypeScript/JavaScript, Go, Rust and Java get scoped resolution; every other language is still matched by name. How it works: a call's caller is the function whose lines contain the call site, never a function elsewhere with the same name. A callee is looked up only among symbols of the caller's language family (TypeScript/JavaScript/Vue/Svelte, C/C++/Objective-C and Java/Kotlin/Scala are one family each), the way the language binds it: for the five languages a bare call in the caller's file, its imports (resolved to project files, following re-exports, module-level values and submodules: Python modules and packages, relative TS paths, Go package directories, Rust `use` paths, Java classes and static imports), its package or its enclosing class, and nothing else — so built-ins and library calls get no edge; a call on a receiver through the receiver's declared type (`self`/`this`/`super`, `Self`, class and module names, constructors, typed parameters, variables, fields and module-level values, declared return types, base classes, Go embedding), never by name after a typed step, and only on an untyped receiver — or a class with a base the resolver cannot resolve, or (Rust) a method a project trait declares, since `impl Trait for Type` is recorded as a base — by method name, never to a free function. A local of the called name shadows a function, Java overloads are chosen by argument count, and two candidates are both linked as `ambiguous` while three or more get no edge. Calls that get no edge are counted per run and reported (see Added). Dispatch is linked to the statically bound declaration, so an interface or abstract method's implementations get no callers through the interface. See `docs/guides/call-resolution-limitations.md` for the step-by-step numbers, the real-repository checks, the cost on Django (54.5–55.9 s vs 51.6–54.1 s, peak RSS slightly lower) and what is still not modelled. The label meanings are unchanged in name; `name-match` now means "the only candidate in the nearest scope". Go and TypeScript interface methods, TypeScript abstract classes and abstract methods are now extracted as symbols, and Go methods on generic receivers are named `Repo.Add` instead of `Repo[T].Add`. Re-run `myc analyze` to rebuild the call graph.

### Fixed
- **`myc analyze` no longer overflows the stack on Java code where a class extends a nested type (`class X extends Outer.Base`) (#177).** Resolving the base looked up `Outer` among X's own members. That lookup resolved X's bases again, with the recursion depth reset to 0, so spring-framework aborted after parsing.
- **Java call binding (#177).** These five gaps were found on the #177 dev set, so they are measured there (see Added):
  - annotation elements are methods (`ann.value()` gets a target);
  - a local variable or field no longer hides a method of the same name;
  - `Outer.this.m()` is a call on the enclosing instance;
  - selecting overloads by arity knows varargs, so `get("/")` no longer binds to `get(URI)` alone;
  - a bodiless method whose annotations stand on their own line keeps its parameter count.
- **A read during an index rebuild no longer panics in Lance or reads a torn index (#175).** The rebuild swapped the new index directory in at `data/<repo-id>`, and every reader resolved each file through that path. A swap between Lance listing a table's newest manifest (name and size) and reading it gave Lance the size of one generation's manifest and the bytes of the next one's, which has the same name because version numbers restart: `attempt to subtract with overflow` at `lance-2.0.0/src/dataset.rs:660` in debug builds (a `JoinError` in `concurrent_rebuilds_never_mix_generations_in_one_call` on macOS CI). In release builds the subtraction wraps; the graph cache's fingerprint check discarded those reads, but readers without it (the CLI hooks, direct `Store` users) could combine tables of two generations. Now a full analysis moves the finished build to `data/.generations/<pid>-…/` and atomically points `data/<repo-id>` — a relative symbolic link — at it; `Store::open`/`open_existing` open the link's target (`myceliums_storage::resolve_index_dir`, `Store::path`), so a store reads one generation. A generation is never rebuilt or truncated in place: `Store::ensure_symbols_dim` and `Store::delete_repo_data` refuse to drop, recreate or empty tables of a published generation (`Store::is_published_generation`); only appends (incremental `--watch` updates, background embeddings, compaction) add new Lance versions, under new file names. `myc analyze` (also the session hook and full `--watch` runs) now builds next to the live index and swaps it in, as the MCP `analyze` tool does, instead of emptying and rebuilding the live index in place; a failed run leaves the previous index as it was. `GraphService` binds each cached store and table to its generation (the `IndexFingerprint` records it) and moves an unpinned snapshot to the new generation's store. The previous generation is deleted after the swap, renamed to `<name>.deleted` first so a reader still on it finds it complete or not at all; such a read fails with `IndexChanged`, and a `Store` whose generation is gone returns `NoIndex` instead of empty tables (and opening it no longer recreates an empty directory). A panic inside a table read becomes an error (`IndexChanged` if the index changed meanwhile) as an extra safeguard. Measured with the new stress test `reads_racing_many_rebuilds_never_panic_or_tear` (150 rebuilds, 6 readers, debug build, macOS): 13 of 30 runs panicked before, 0 of 30 after; with Rust's overflow checks off (release semantics) direct `Store` readers combined two generations in about 4 % of reads before and in none after. **Layout:** existing indexes (plain directories) stay readable and become links at their next full analysis; a reader that opened such an index before that analysis can still meet the old race once. Recovery handles both layouts, deletes generations no link points at, and `delete`/`myc delete`/`myc clean --orphans` remove a link with its generation (`myceliums_core::remove_index`). Where no link can be made (Windows), the build directory is swapped in itself, as before, and the race remains there.
- **Community detection no longer stalls on large graphs (#172).** `graphrs`' Leiden, which `myc analyze`, the MCP `analyze` tool and every tool that groups symbols by community ran, is quadratic in the number of nodes: each move clones the source community to compute a delta, removing an emptied community renumbers the whole node table, the local move rebuilds its queue set after every move, and the refinement scans every community of the graph for each node. Measured with `community_bench` (release build, same index): Flask 3.1.3 (1,671 nodes) 2.2 s → under 0.01 s; Django 5.1.4 without `tests/` (13,250 nodes) 128 s → 0.08 s; vuejs/core v3.5.46 (17,584 nodes) 161 s → 0.04 s; Django 5.1.4 with `tests/` (43,236 nodes, 85,676 symbol pairs) not finished after 1,200 s (#171 saw more than 1.5 h) → 0.2 to 0.4 s, converged after 11 to 23 iterations. The replacement (`myceliums_core` internal module `leiden`) is Leiden for modularity on a compressed adjacency list, each local-move, refinement and aggregation pass linear in the edges, with a fixed random seed. Modularity is equal or higher: Flask 0.728 → 0.740, Django without tests 0.843 → 0.870, Vue 0.883 → 0.901, Django with tests 0.841. The test-helper hubs (`SimpleTestCase.assertRaisesMessage`, 1,543 neighbours) were not the cause; the graph keeps them. `get_community_metrics` computes modularity with the standard formula (it summed `k_i k_j / 2m` over edges instead of node pairs) and cohesion over distinct symbol pairs, and no longer reports zeros when two symbols share several relationships (graphrs rejected the duplicate edges).
- Vector search no longer returns symbols that have no vector (#157): their placeholder was a zero vector, which scored cosine 0.5 and filled semantic and hybrid results of a partially embedded index; it is null now, which the search skips.
- Model files are downloaded by myceliums itself (ureq with native-tls, as hf-hub used; #157): over HTTPS only, redirects included (a redirect to plain HTTP fails); never past the pinned size (more bytes abort the download and remove them); a partial download is resumed only when the server answers with exactly the range asked for, else it starts over; the file is synced before it is renamed into place; and a PID lock per file (`<file>.part.lock`) keeps two processes from writing one partial file — the second waits and uses what the first downloaded. A stopped download keeps its partial file, and the progress is reported.
- Tokenizing for a local model holds a bounded amount of memory (#157): texts are tokenized and embedded in slices of 4,096 (the tokenizer sees 256 at a time), a text longer than the window is cut at the end of the first word past the window plus a 16-token margin before it is tokenized — the kept ids are those of the whole text, checked against all eight registry tokenizers — and only ids and type ids are kept. Tokenizing 20,000 texts of 8 KB with the default model's tokenizer raised peak memory by 3.2 GB at once and by 0.18 GB in groups (`tokenizing_a_large_corpus_*`, ignored tests). `EmbedStats::truncated_texts` counts the texts the window cut, not every text that fills it.
- Loading a model no longer holds the model cache's lock: a first load (and download) runs on the blocking pool, and lookups of other or already loaded models do not wait for it (#157).
- `myc analyze` re-analyzes an index whose vectors come from another embedding model, template or chunking than the project now configures, instead of reporting "Using cached analysis" until `--force` (#157).
- Incremental runs keep embedding with the index's own template when this build still produces it, instead of refusing every index built by an earlier template (#157); only an unknown or unrecorded template is refused, as before.
- `jina-embeddings-v2-base-code` claimed an 8,192-token budget but was always cut at 512 tokens by fastembed's default; every registry model now declares the 512-token window it embeds with (#157).
- Correctness follow-ups (#118): a Cypher query with an unterminated string, an unknown character or an integer out of range fails with the position (`Invalid query: unterminated string literal (no closing ') at position 26`) instead of being cut short silently (a trailing `;` is accepted); the Cypher guide and `myc query` examples used labels the executor rejects (`Function`, `Class`, `Community`) and now use `CodeSymbol`/`File` with `WHERE s.kind = ...`, checked by a test; incremental re-indexing (`myc analyze --watch`, `Analyzer::analyze_files`) applies the size, line-length, minified and binary skip rules of a full analysis; `myc analyze` and the MCP `analyze` tool report the files they skipped and why; a TypeScript `export { Bar as Foo }` no longer shadows an imported `Foo` inside its module; a `myc setup-claude` block that pushes CLAUDE.md past `max_file_size_kb` makes the index stale; a read of a registered repository whose index is missing says to run `myc analyze` (CLI) or is an `isError` result (MCP), and `analyze` rebuilds such a repository instead of answering from the cache; `StorageError` no longer prints the wrapped error twice in a chain and keeps nested contexts; `Store::open_existing` removes the empty directory LanceDB's `connect` creates when the index disappears during the call (Unix).
- Files written by `myc setup-claude` after `myc analyze` no longer make the index look stale (#151). Freshness — the MCP `Index:` line, the `analyze` tool's re-index decision and the non-git cache check — counts only files the analysis would index, through one predicate shared with the analyzer's file walk (`myceliums_core::index_scope::IndexScope`: hidden and build directories, known extensions, `include`/`exclude`/`skip_patterns`, size limit), plus `.myceliums.toml`. `.mcp.json` and `.claude/` therefore never count, and the routing block in CLAUDE.md / AGENTS.md is left out of the index (Markdown/MDX only; elsewhere the markers are plain text), so a Markdown file whose text outside the block is what the analysis indexed — compared with a fingerprint recorded at index time, or else with the committed version — is no change. An indexed file that grew past the size limit counts as changed. Before, the MCP `analyze` tool re-indexed after `setup-claude`; in the #125 runs that once ran into the client's 300 s timeout.
- A full re-analysis no longer drops existing embeddings (#151). Symbols whose embedding text is unchanged take their vector over from the index being replaced (same model, current vector geometry and embedding-text template only), so `skip_embeddings` / `--skip-embeddings` / the `myc session` default and a model that fails to load or embed leave only new or changed symbols without a vector; before, such a run replaced an embedded index with one without vectors (seen in #125 when an agent called `analyze` with `skip_embeddings`). A re-index with embeddings now embeds only the changed symbols. `analyze` says how many vectors were kept and warns when symbols have no vector because embedding was skipped, and a cached answer for an index built without embeddings reports `0/N` instead of `N/N`.
- The SessionStart hook's output now reaches the model, and session start no longer waits for an analysis (#152). `myc session . --yes` prints one JSON object whose `hookSpecificOutput.additionalContext` adds a single line of at most 280 characters (about 60 tokens) to the session. The line holds the repository id, the index state and `find_callers` / `impact_of_change` / `search_code` for structural questions. The index state is the freshness from the same check `myc callers` uses, or "stale, re-indexing in the background", "no index yet, building in the background" or "already running". Before, the status was only a `systemMessage`, shown to the user and not to the model; that status line stays, and also goes to stderr. A missing or stale index used to be re-analyzed in the foreground for up to 300 s. Claude Code waits for SessionStart hooks, so the first response waited too, and `myc analyze` printed its report onto the hook's stdout, where Claude Code would have added it to the model's context as plain text. The hook now starts a detached `myc analyze` in its own session (`setsid`), with output appended to `<data dir>/logs/session-<repo id>.log`, and returns at once (0.05 to 0.11 s on flask, debug build). The analysis takes the #98 lock that MCP `analyze` uses; while it is held the hook starts nothing and reports "already running". `--timeout` is now ignored. Skips and errors add no context and still exit 0. `myc setup-claude` gives the handler `"timeout": 15`; the command is unchanged.
- Opening a store or team store at a path that is not valid UTF-8 returns `StorageError::NonUtf8Path` instead of panicking (#101).
- Reading a registered repository whose index is missing (never built, deleted, or mid-swap during a rebuild) no longer creates an empty database and answers with zero counts: CLI read commands fail with `no index at <path>` and the dashboard answers 404 (#101).
- The `myc serve` API answers every failure with a status and `{"error", "next"}` instead of a `404` with an empty body (#118): an unknown `repo_id` is a `404` listing the registered ids, a registered repository without an index a `404` naming `myc analyze <path>`, an index replaced mid-request a `503` with `Retry-After`, semantic search on an index without embeddings a `409`, and a storage or computation failure a `500` with the cause. A table that fails to load fails the request instead of being served as empty (partial graphs, zero counts). The dashboard shows the message instead of an empty graph.
- `myc diff` compares with the previous analysis, chosen like the MCP drift tool (`myceliums_core::previous_snapshot`), instead of the latest snapshot, which was the current analysis itself (#97).
- Graph diffs never worked: every analysis overwrote the only snapshot, keyed by symbol uids that each analysis generates anew, and nothing wrote the versioned snapshots `snapshot_diff` compared. Each analysis now records a versioned snapshot (the newest 10 are kept) keyed by file, qualified name and kind, and `detect_architecture_drift` compares the previous analysis with the current graph by default (#97).
- The Claude Code PostToolUse hook read tool results as `{"text": ...}` JSON and their first line, which since #96 is the `Index:` line; it now reads plain text, skips the freshness line, and knows the new tool names (#97).
- Cypher `GROUP BY` on a property (`RETURN s.kind, count(s)`) grouped every row under `null`, and groups came out in a different order on every run; they are now keyed by the evaluated property and keep first-seen order (#96).
- The MCP `detect_impact` and `rename_symbol` outputs listed only affected files and `Rename: ? -> …` because they read JSON keys that do not exist; they now render the changed and affected symbols and each edit (#96).
- The PostToolUse hook that `myc setup-claude` installs now matches myceliums tools: Claude Code compares a matcher of only letters and `_` as an exact tool name, so the old `mcp__myceliums__` matched nothing; it is now `mcp__myceliums__.*` (#126).
- `myc setup-claude` refuses to rewrite a settings or MCP config file it cannot parse instead of replacing it with its own content (#126).
- `--strict-embeddings` is honored in the session bootstrap path (#69).
- The `embeddings` feature gate lost in #43 is restored (#70).
- Benchmark baselines are content-addressed instead of tied to a git commit (#86).
- Lint findings in test code, now that clippy covers `--all-targets` (#81–#85, #87).
- Hybrid search returns tied results in a fixed order instead of a per-process random one (#92).
- The manual benchmarks workflow no longer hides failing benches behind `continue-on-error` (#92).

### Removed

- The `verified_metrics` and `agent_tasks` benches and the hard-coded scenario estimates behind them, which measured nothing (#92).
