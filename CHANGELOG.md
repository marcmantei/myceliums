## [Unreleased]

### Breaking
- **The default embedding model is `jina-embeddings-v2-base-code`, with embedding-text template 2 and chunking on (#157).** Eleven model × template × chunking variants were scored on the 168-query real-repository set. Jina with template 2 was the only one whose gain over `multilingual-e5-small` held on the held-out queries: +0.070 [+0.010, +0.128] (mean of semantic and hybrid nDCG@10). On the golden set it raises nDCG@10 by +0.114 [+0.035, +0.196] in semantic and +0.086 [+0.024, +0.150] in hybrid search; the golden baseline was re-recorded for it. The price is indexing time. A first index takes about 4.4× as long as with e5-small (release build, 4 vCPU). The vectors take twice the space (768 dimensions), a query takes about 35 ms instead of 12 ms, and the download is 644 MB. That is over the index-time limit fixed before measuring (2.5×): **the index-time budget was waived by owner decision — 4.4× first index; incremental runs reuse vectors.** The protocol by itself kept e5-small, and jina was chosen after the held-out results were known. Protocol, all tables and limits: `crates/myceliums-benchmarks/benchmarks/METHODOLOGY.md`. Before a first index, `myc analyze` now says that it takes the longest, gives the download size when the model is not cached, and names the fast option. The MCP `analyze` tool answers once the graph is built and embeds in the background (see Added). The fast option is `model = "multilingual-e5-small"` with `chunking = false`: multilingual queries and a 4.4× faster first index. **Upgrading:** every existing index is re-embedded once, on its next `myc analyze` or MCP `analyze` (which re-analyzes an index whose recorded embedder differs from the configured one); after that, runs reuse vectors again. If `.myceliums.toml` names no model, the project moves to jina. If it names `model = "multilingual-e5-small"` (earlier `myc init` versions wrote it), it stays on e5-small with template 2 and chunking. Add `chunking = false` to keep the previous configuration exactly and skip the re-embed.
- **`myc mcp` now exposes the core toolset by default: 9 tools instead of 55** (#97). `search_code`, `explain_symbol`, `find_callers`, `find_callees`, `impact_of_change`, `trace_flow`, `find_dead_code`, `list_repos` and `analyze` are named after the questions agents ask and carry `_meta["anthropic/alwaysLoad"]`, so Claude Code loads them up front instead of deferring them behind tool search (the #99 pilot: 0 of 90 sessions called a myceliums tool). The other tools are opt-in by group — `graph`, `review`, `architecture`, `knowledge`, `email`, `cross_repo`, `admin` — with `myc mcp --toolsets core,architecture,...` or `myc configure --set mcp.toolsets=...`; `--toolsets all` restores every tool. Clients that call a non-core tool by name must add its group.
- Duplicate tools are merged; the old names stay as deprecated aliases in the `deprecated` group (part of `all`) for one release, each description naming its replacement: `context_search`, `search_documents` (which was `context_search` under another name, not a BM25 document search), `semantic_search`, `hybrid_search` → `search_code` with `mode`; `symbol_context`, `get_symbol_definition` → `explain_symbol`; `get_callers`, `get_callees` → `find_callers`, `find_callees`; `detect_impact` → `impact_of_change`; `get_graph_diff`, `snapshot_diff` → `detect_architecture_drift` (#97).
- **Upgrading:** the old tool names are not in the default profile. A client that still calls `context_search`, `symbol_context`, `get_callers`, `detect_impact`, ... gets "tool not found" until it moves to the new names; to keep the old names for this release, run `myc configure --set mcp.toolsets=deprecated` (or `myc mcp --toolsets core,deprecated`) (#97).
- Without `repo_id`, tools no longer fall back to the most recently analyzed repository: they use the indexed repository containing the working directory (the deepest, matched on whole path components — `/x/app-two` is not inside `/x/app`) and otherwise fail with `No index covers <dir>` and a `Next:` step. Every `Index:` line names its repository (`Index: my-app, commit …`). Overloads in one file are ambiguous, as in `myc callers`, and are picked with `file_path:qualified_name:line` (#97).
- Text tools return their answer as plain text content; it is no longer wrapped as `{"text": "..."}` JSON and duplicated in `structuredContent`, and these tools have no `outputSchema`. Tools with a natural record or list shape (`find_callers`, `find_callees`, `find_dead_code`, `list_repos`, `get_stats`, `get_file_symbols`, `get_communities`, `get_community_detail`) return typed `structuredContent` with an output schema. `list_repos` is now structured. The `TextOutput` type is gone from the `myceliums-mcp` crate, and `run_mcp_server`/`run_mcp_http_server` take the `Toolsets` to serve (#97).

- **Library API: `myceliums-storage` and `myceliums-core` return typed errors instead of `anyhow::Error`** (#101). Storage functions return `myceliums_storage::StorageError` (`NoIndex`, `RepoId`, `Database`, `Arrow`, `Io`, `Json`, `InvalidData`); core functions return `myceliums_core::MyceliumError`, which gains `Store(StorageError)` (a repo-id error from storage stays `Repo`), `ParseAborted`, `Cancelled` and `Json`, plus `parse_abort()` and `is_cancelled()` in place of `anyhow` downcasts; its `Storage(String)` ("no repository registered") is renamed `NotAnalyzed(String)` (#118). Code using `anyhow` keeps working through `?`. Unused dependencies are dropped: `anyhow`, `uuid`, `chrono`, `dirs` from storage, `tower-http` from http, `serde`, `tracing` from cypher.
- **Upgrading indexes built before embedding metadata was recorded** (#92, #118): an index with vectors but no recorded embedding model cannot be searched by meaning — `search_code` falls back to keyword search in `auto` mode and says so for `semantic`/`hybrid`. Such vectors predate the current embedding text and geometry anyway; run `myc analyze <path> --force` (or `analyze` with `force`) once to re-embed.

### Added
- **Embedding stack measured end to end (#157).** Local embedding models run in-process on ONNX Runtime (through `ort`, `tokenizers` and `hf-hub`, the crates and versions fastembed already locked — no new crates in the dependency tree; the reranker stays on fastembed). Every registry model is pinned to a HuggingFace commit and its weights to a SHA-256, checked after download (size on every load); graphs with external weights load. Texts are sorted by token count and batched up to a token budget (`[analysis] embedding_batch_tokens`, default 16,384) instead of 256 random texts padded to the longest — on the hosted runner `multilingual-e5-small` (template 1) indexed the four evaluation repositories in 535 s instead of 1,750 s (debug builds of the evaluator, runs 44884767742 and 44434858317), and in about 220 s in a release build. `MYCELIUMS_EMBEDDING_THREADS` caps the session's CPU threads; `myc analyze` and the MCP `analyze` tool show embedding progress.
- Embedding-text template 2 (#157): language, kind and `file::qualified.name`, the name split into words, decorators and signature, the doc comment or docstring, then the body without the signature line and docstring it repeats, lines trimmed. Doc comments directly above a symbol (`///`, `/** */`, `//`, `#` lines) are extracted at parse time into `SymbolMetadata.doc`; BM25 does not read them. Template 2 is the default: chunking (on by default) needs it, and the models evaluated in #157 were measured with it. Template 1 stays for the e5 family with `chunking = false` (the fast option) and for remote models.
- Chunking of long symbols (#157, `[embedding] chunking`, on by default; `false` turns it off): the header chunk plus overlapping 512-token body chunks counted in the model's own tokens (64 tokens overlap, at most 16 vectors per symbol; classes, interfaces, enums and modules are not chunked), stored in a `chunks` table keyed to the symbol. `Store::vector_search` scores a symbol by its best vector and returns one row per symbol, exactly (`chunked_search_is_the_brute_force_top_k`). Vector reuse (#151) carries chunk vectors over a re-index and reuses unchanged body chunks of changed symbols by text hash. Measured: +0.026 to +0.050 on the 60 real-repository queries whose answers include a long symbol for four of five models (+0.033 [+0.003, +0.066] for `multilingual-e5-small`), no measurable change over all queries.
- Registry entries `granite-embedding-small-english-r2`, `coderankembed` and `gte-modernbert-base`; the README's model table lists measured quality, index time, query latency, memory, download size and license for every evaluated model.
- Embedding-variant evaluation (#157): `real-repo-eval --model/--template/--chunking/--modes/--no-demotion/--repos` records indexing time, texts, chunk vectors, vector and disk bytes, semantic query latency, peak memory, download size and license, and scores a long-symbol slice; `real-repo-compare` turns variant reports into quality, cost and budget tables, the dev selection and its held-out confirmation; the `Retrieval Quality (real repositories)` workflow takes a `variants` matrix (and `release` for cost measurements with the incumbent re-measured on every runner).
- **The MCP `analyze` tool embeds in the background (#157).** It builds the graph without running the model (`Analyzer::defer_embeddings`: unchanged symbols still take their vectors over from the previous index), swaps the index in and answers; the other symbols are then embedded on a blocking-pool thread (`myceliums_core::embed_pending`). A first index with the default model — a 644 MB download and minutes of inference — therefore never runs inside one tool call, which clients abandon after a few minutes. The job writes no table the graph is read from until it is done: it stages each symbol's vector as chunk row 0 next to its body chunks, every 1,024 symbols or 20 s, where vector search already finds it, and keeps the accounting in the index metadata; both tables are left out of the graph cache's fingerprint, so cached graphs stay and running calls do not fail with "the index was replaced". At the end it moves the staged vectors onto the symbols' rows in one write and compacts the tables; `search_code` and `impact_of_change` retry once if that write lands mid-call. The job holds the repository's analysis lock; the Index line of every result (with the model download's progress and an estimate of the time left), the search warnings and `server_stats` show its progress; `auto` search uses keywords until the first vectors are stored. It stops between two model batches — or between two reads of the model download — when the server stops serving (stdin closed, Ctrl-C), and the process waits for it at most 5 s; an `analyze` that re-analyzes the repository (another embedder, a moved HEAD, `force`) stops it first. A stopped or failed job keeps what it stored and the next `analyze` of the fresh index resumes it; a job that panics ends as failed instead of staying "running". A cached index whose recorded embedder (model, template, chunking) differs from the configured one, or that has no embeddings yet, is re-analyzed instead of reported as cached; a partially embedded index says "call analyze to embed the rest".
- Every file a local model loads is pinned (#157): `tokenizer.json`, `tokenizer_config.json`, `config.json` and `special_tokens_map.json` join the weights with a pinned size and SHA-256, checked like the weights; a file the revision lacks is pinned as absent and never fetched. `HF_ENDPOINT` must be an `https://` URL.
- Agent benchmark variant matrix (#125): 20 harder multi-hop tasks (transitive callers, blast radius, same-named symbols, tests that reach a function, call chains) with gold sets from call graphs built by compiler tooling (`gotool edges`, `ts_edges.js`, `py_edges.py`, `hard_tasks.py`); conditions A (MCP server), C (+ `myc setup-claude --no-agent`) and E (+ `code-explorer` subagent); `agent_eval.py probe` checks a variant's setup against a local mock of the Messages API without calling a model. Result (116 sessions, Claude Code 2.1.329): the agent called myceliums in 80 % (A), 100 % (C) and 97 % (E) of sessions, never delegated to the subagent, and accuracy, tokens and cost did not differ measurably between the variants, all near the ceiling. An earlier, smaller version of the task set was at the ceiling without myceliums (10 of 10 calibration sessions).
- Unlinked calls are accounted for (#139): every analysis counts how many call sites got a CALLS edge and why the others did not (more than two candidates, a library target, a call through a variable, nothing in scope, outside any function); `myc analyze` and the MCP `analyze` tool print the counts, the index keeps them (`index_meta` key `call_resolution`), `find_callers` reports the unlinked call sites named like the symbol (`unlinked_call_sites`) and `impact_of_change` adds the same note for the changed symbols.
- A held-out real-repository CALLS set (#139): 52 call sites from flask, requests, gin and hono, drawn at random and traced by hand, scored by `graph-eval` next to the fixture gate when the pinned checkouts are present; reported, never gated.
- Per-call observability for the MCP server (#98): every tool call runs in one `tool_call` tracing span (tool, toolset, `repo_id`, `duration_ms`, `result_bytes`, `approx_tokens` = bytes/4, outcome `ok`/`is_error`/`protocol_error`/`cancelled`), applied once at the dispatch layer, and logs one line to stderr. `myc mcp` now logs at INFO for `myceliums_mcp` and WARN for `myceliums_core` without `RUST_LOG` (everything else stays at errors only; `RUST_LOG` overrides), writes colour codes only to a terminal, and takes `--log-format json` for one JSON object per line. Stdout stays the stdio transport.
- Local tool-call statistics (#98): the opt-in `server_stats` tool (toolset `admin`) and `myc mcp --stats-file <path>` report per-tool calls, `isError` results, protocol errors, p50/p95/max latency and result bytes. In memory only, bounded (one entry per catalog tool, percentiles over the last 1024 calls), never sent over the network.
- `analyze` sends MCP progress notifications (0–100 with a message per phase) when the request carries a `progressToken` (#98).
- Agent integration kit (#126): `myc callers`, `myc callees`, `myc impact <symbol|file>` and `myc context` print compact, token-budgeted answers with file:line and index freshness (`--json` for harnesses; ambiguous names list candidates); `myc hook-grep` is a never-blocking Claude Code PreToolUse hook that answers a grep for a known symbol with the matching `myc` call; `myc setup-claude` also writes a versioned CLAUDE.md routing block and a `code-explorer` subagent, each with an opt-out flag; `myc setup-codex` writes the routing block into AGENTS.md; `examples/agent-sdk-prefetch/` prefetches a context pack for a Claude Agent SDK agent; guide in `docs/guides/agent-integration.md`. Effects of the layers were measured in #125 (see below).
- `myc setup-claude` at user scope sets `"alwaysLoad": true` on the `myceliums` entry when `mcp.toolsets` is the default (left out when groups are added; `--no-always-load` writes `false`), registering it with `claude mcp add-json` so the key is kept. A project's shared `.mcp.json` never gets the key: the core tools load up front through their own `_meta`, and the docs show a personal local-scope override. The routing block (v2) and the `code-explorer` subagent (v2) name the core tools (#97).
- `explain_symbol` shows at most `max_source_lines` (default 120) of a symbol's source and says how to get the rest; `find_dead_code`'s `path` accepts absolute paths inside the repository and unique file suffixes, and a path that matches nothing is an `isError` result instead of an empty list; `search_code` with `mode=semantic`/`hybrid` on an index without embeddings is an `isError` result instead of loading (or downloading) a model (#97).
- The MCP tools resolve names and walk callers, callees, dependents and call chains through `myceliums_core::navigation`, like `myc callers/callees/impact`: qualified suffixes (`Item.AsString`) resolve, functions and types win over same-named variables, and an unknown name suggests similar ones. Core gains `walk_calls_reached`, `dependents_reached` and `call_chains` (#97).
- `search_code` mode `auto` (default): hybrid search when the index has embeddings, keyword search otherwise, without loading a model for an index built with `skip_embeddings` (#97).
- `impact_of_change` answers for a symbol or a file — every caller and importer, transitively, with the files to update — as well as for a diff; `trace_flow` lists the shortest call chain between two symbols and every symbol on such a chain; `find_callers`/`find_callees` report `via` for indirect hits; `find_dead_code` takes a `path` and an optional `repo_id` (#97).
- Agent benchmark (`evals/agent/`): 30 code-understanding tasks on pinned fzf, hono and FastAPI checkouts, run by a headless Claude Code agent with and without the myceliums MCP server and graded against hand-verified answers, plus a tool-selection eval over the live `tools/list`. The first pilot run and its report are committed (#99).
- Retrieval-quality measurement against a golden dataset, reported on every PR (#76, #34).
- The retrieval evaluation scores semantic, hybrid and hybrid+rerank search through the shipped code paths, adds hit@k, nDCG@10 and R-precision with per-intent and per-query results, and reports paired bootstrap confidence intervals. CI caches the model weights, scores all four modes and fails only on a regression of at least 0.02 whose 95% interval lies below zero — per comparison, not corrected for multiple comparisons (#92).
- `ann-recall` measures the recall of the IVF-PQ vector index against exact search (#92).
- Supply-chain checks in CI: `cargo-deny` (advisories, licenses, sources), Dependabot for Cargo and GitHub Actions, an MSRV job (`rust-version = "1.88"`), and the test suite on macOS (#90).

### Changed
- **Search ranks test code below product code** (#146). At index time every symbol is classified as test or product code by unambiguous language conventions — test directories (`tests/`, `__tests__/`, `testdata/`, `runtime-tests/`, a root-level `test/` or `spec/`, `src/test/java`, .NET `*.Tests/`, …), test file names (`*.test.ts`, `*.spec.ts`, `*.test-d.ts`, `*_test.go`, `test_*.py`, Django's `tests.py`, `*_spec.rb`, `*Test.java`, …) and, inside Rust files, items under `#[cfg(test)]` and `#[test]` functions; shipped test helpers (`django/test/`, `test_utils.py`, a `test-utils` package) stay product code — and stored in the symbol's metadata (`SymbolMetadata.test`, `CodeSymbol::is_test`). Keyword, semantic, hybrid (the fused list, before it is cut to the page) and reranked search then place a test symbol at position `p` as if it were at `p / 0.2` (`DEFAULT_TEST_WEIGHT`), so it lands no lower than `5p`: a down-weight, not a filter. `search_code` takes `tests=demote|include|prefer` and `myc search` / `myc semantic-search` take `--tests`; `explain` names the rows that were moved down. Only search reorders: graph tools, `myc context` and the cross-repository tools keep test code in place; the `myc serve` HTTP API's semantic search, semantic neighbours and knowledge search demote too and take `?tests=demote|include|prefer` (#150). **Existing indexes are re-analyzed once:** an index built before this release carries no classification (`RepoInfo.classification_version` 0), so search on it ranks tests as before and says so, and the next `myc analyze` / `analyze` rebuilds it even when nothing changed — a full re-parse; the classification is not part of the embedding text, so the rebuild takes the existing vectors over (#151) instead of re-embedding. `Store::vector_search` now returns each hit's metadata. Measured on the real-repository set (unreviewed agent labels; linux-x86_64): against tests included, weight 0.2 raised held-out nDCG@10 by +0.088 [+0.055, +0.124] (keyword), +0.081 [+0.052, +0.113] (semantic), +0.084 [+0.056, +0.115] (hybrid) and +0.106 [+0.070, +0.145] (hybrid+rerank), in every repository and mode; the price is paid by searches *for* tests, whose hit@10 stays at 0.55–0.75 per mode (0.70–0.75 without demotion) while their nDCG@10 drops by 0.13–0.33 — pass `--tests include`/`prefer` for those. `real-repo-eval` also scores every mode with tests included, 20 test-seeking queries (`real-repos/test-seeking.json`) whose labels are tests, and sweeps the weight on the dev split. Library API: `rerank_results` and `hybrid_search_explain` take the test policy, `HybridParams` gains `tests`, `search_symbols_ranked` and `semantic_search` are new.
- **CALLS edges are resolved by scope, imports and declared types instead of a global name map** (#139). Measured: on the #94 fixture gold set call precision went from 0.57 to 1.00 and recall from 0.56 to 0.996 — but the rules were developed while reading those fixtures, so that is their coverage, not an estimate for unseen code; on a held-out sample of 52 call sites drawn at random from flask, requests, gin and hono and traced by hand (not reviewed yet), precision went from 0.48 to 0.95 and recall from 0.45 to 0.95, with wide intervals (22 pairs with a project target). Only Python, TypeScript/JavaScript, Go, Rust and Java get scoped resolution; every other language is still matched by name. How it works: a call's caller is the function whose lines contain the call site, never a function elsewhere with the same name. A callee is looked up only among symbols of the caller's language family (TypeScript/JavaScript/Vue/Svelte, C/C++/Objective-C and Java/Kotlin/Scala are one family each), the way the language binds it: for the five languages a bare call in the caller's file, its imports (resolved to project files, following re-exports, module-level values and submodules: Python modules and packages, relative TS paths, Go package directories, Rust `use` paths, Java classes and static imports), its package or its enclosing class, and nothing else — so built-ins and library calls get no edge; a call on a receiver through the receiver's declared type (`self`/`this`/`super`, `Self`, class and module names, constructors, typed parameters, variables, fields and module-level values, declared return types, base classes, Go embedding), never by name after a typed step, and only on an untyped receiver — or a class with a base the resolver cannot resolve, or (Rust) a method a project trait declares, since `impl Trait for Type` is recorded as a base — by method name, never to a free function. A local of the called name shadows a function, Java overloads are chosen by argument count, and two candidates are both linked as `ambiguous` while three or more get no edge. Calls that get no edge are counted per run and reported (see Added). Dispatch is linked to the statically bound declaration, so an interface or abstract method's implementations get no callers through the interface. See `docs/guides/call-resolution-limitations.md` for the step-by-step numbers, the real-repository checks, the cost on Django (54.5–55.9 s vs 51.6–54.1 s, peak RSS slightly lower) and what is still not modelled. The label meanings are unchanged in name; `name-match` now means "the only candidate in the nearest scope". Go and TypeScript interface methods, TypeScript abstract classes and abstract methods are now extracted as symbols, and Go methods on generic receivers are named `Repo.Add` instead of `Repo[T].Add`. Re-run `myc analyze` to rebuild the call graph.
- The graph-accuracy evaluation is a CI gate (#139): `graph-eval --check-baseline` fails on a drop in CALLS precision or recall of at least 0.02 whose paired bootstrap 95% interval lies below zero (the retrieval gate's rule), and on any CALLS edge between two languages. Its report shows 95% Wilson intervals; the baseline is re-recorded.
- The MCP server's graph cache is bounded and each tool call reads one consistent snapshot (#129). At most `mcp.graph_cache_max_repos` repositories (default 8) and an estimated `mcp.graph_cache_max_mb` MiB (default 1024; `0` = no size bound) stay cached, least recently used evicted first; repositories no longer in the registry are dropped on the next call. `GraphService::graph(repo_id)` checks the registry and the index fingerprint once per call and returns a `RepoGraph` through which every table comes from the same index generation, also when one snapshot is read concurrently; vector search results are checked with `RepoGraph::verify`. A call that would mix two generations — or whose read failed because a swap removed its files — fails with an `isError` "retry" result instead (`MyceliumError::IndexChanged`). The registry is parsed once per call (`GraphService::graph_in`). The per-table methods `GraphService::symbols()`, `relationships()`, `files()`, `communities()` and `processes()` are replaced by the same methods on `RepoGraph`. `IndexFingerprint` now also records directory identities and a hash of each table's newest manifest, so a table dropped and recreated within one filesystem-timestamp tick (an embedding-dimension change, a rebuild) is detected.
- **MCP `analyze` no longer deletes the previous index before rebuilding** (#98). It builds the new index in `data/.staging/` and swaps it in when complete — one `renameat2(RENAME_EXCHANGE)`/`renamex_np(RENAME_SWAP)` call on Linux/macOS, two renames with undo elsewhere — invalidating the graph cache at the swap; a failed or cancelled analysis leaves the previous index usable and removes the staging directory. Cancellation reaches the analyzer (`Analyzer::with_cancel`: checked between files, between phases and before embedding). Rebuilds killed outright are recovered at the next `myc` command, MCP server start or rebuild (`myceliums_core::recover_leftovers`: an unfinished swap's previous index is renamed back unless the journal records the commit — its journal is kept until then; read paths (`Store::open_existing`) no longer recreate a missing index directory — other leftovers of dead rebuilds deleted; running ones untouched), and `myc clean --orphans` skips `data/.staging/` and `data/.locks/`. New repository ids never start with `.` (a folder `.foo` gets `_foo-<hash>`), so no repository can collide with these directories; legacy dot ids stay readable, and re-analyzing such a project replaces its legacy registry entry. The whole build runs on a blocking thread instead of the async runtime (only parsing did before), so other calls are answered meanwhile. A second `analyze` of a repository that is being analyzed — by the server or by `myc analyze` — returns an `isError` result (`Analysis already running …`), and `delete` (MCP and `myc delete`) refuses it too. The analysis lock moved from `data/<repo>/analysis.lock` to `data/.locks/<repo>.lock`, outside the directory a rebuild replaces; `myc doctor` checks both. The parse progress poller can no longer outlive an analysis that failed. `myc analyze` (CLI) still rebuilds in place. `run_mcp_server`/`run_mcp_http_server` take `ServeOptions` (toolsets, stats file); the core gains `StagedIndex`.
- MCP tool contract (#96): failures the agent can act on (unknown symbol or repo, ambiguous name, missing snapshot, file not indexed, `delete` without `confirm: true`) are `isError` results that end with a `Next:` step; bad arguments are `invalid_params`; only server faults are `internal_error`. Every list tool takes `limit`/`offset` with a default and a hard maximum and says `Showing 1-20 of 312 — call again with offset=20` when it cuts; `cypher_query` pages its rows and marks cut cells with `…`. Every graph result starts with an `Index:` line (analyzed commit vs `HEAD`, files changed since indexing, read with `git --no-optional-locks`); when it calls an index stale, `analyze` without `force` re-indexes. `git diff HEAD` for impact analysis also runs with `--no-optional-locks` and a 30 s timeout (`myceliums_core::git_read`). Symbols can be named `file_path:qualified_name`; a name shared by several symbols is an error listing those handles, also for `rename_symbol`. Lists the core builds from hash maps are sorted before paging. CALLS edges record how they were resolved (`exact`, `import`, `name-match`, `ambiguous`) and tools show it. Indexed source, document and email text is framed in `<<<UNTRUSTED <id>` … `>>>END <id>` blocks. All tools carry read-only/destructive/idempotent/open-world annotations; enum-like parameters are enums and numeric ones have bounds in the schema; stale descriptions and the server instructions (which called every tool read-only) are corrected. Without `repo_id`, tools now fall back to the most recently analyzed repo, as documented, instead of the last one by name.
- `myc setup-claude` installs into the project by default (`.mcp.json`, `.claude/settings.json`, `CLAUDE.md`, `.claude/agents/`), so a team can commit it; `--scope user` keeps the previous user-wide install, which `myc setup` and the wizard use. Uninstall removes exactly the myceliums parts at that scope (#126).
- The CLI (including `myc serve`) honours `MYCELIUMS_DATA_DIR` like the MCP server, so CLI commands and hooks read the same index as a server started in the same environment (#126).
- Vector scores use one similarity scale across search paths, and the ANN index is used (#68, #71).
- **Vector search is exact at every repository size — re-run `myc analyze` once to delete old ANN indexes.** Releases before this one built an IVF-PQ index from 5,000 symbols that returned only about 4 of the true 10 nearest neighbours. Searches now bypass any such index and the next `myc analyze` (or any re-embedding) drops it; no approximate index is built any more. Exact search measured 5.2 ms per query at 20,000 symbols (real embeddings) and 15 ms at 100,000 (synthetic). `analysis.ann_threshold` is deprecated and ignored. `ann-recall --sweep` compares index settings on synthetic and real embeddings, and `cargo test` fails if production search stops being exact (#117).
- MCP handlers go through a `GraphService` layer (#37, #53).
- The CLI and the `myc serve` dashboard read indexes through `GraphService`, like the MCP server (#101): `myc stats`, `communities`, `processes`, `query`, `search`, `semantic-search`, `knowledge`, `impact --diff`, `path`, `rename`, `export`, `report`, `wiki`, `diff` and the navigation commands take their tables from one snapshot, and the dashboard keeps graph tables cached across requests while the index is unchanged (bounded by the `mcp.graph_cache_*` keys).
- The MCP crate is split into modules by tool group, and every read tool and resource is served from `GraphService`'s per-repository graph cache: the graph tables are read from disk once, not on every call; `analyze` and `delete` invalidate the cache, and index changes made by another process are detected. The HTTP transport shares one cache across sessions. The `tools/list` output is pinned by a snapshot test (#93).
- The Homebrew tap sync can be re-run manually and is idempotent (#74).
- CI pins every third-party action to a commit SHA, runs with read-only token permissions by default, and builds with `--locked` (#90).
- The index fingerprint covers the version of the embedding-text template and its budget constants. Indexes written by earlier releases are re-embedded on the next full `myc analyze`; until then, incremental re-indexing with embeddings is refused rather than mixing two templates in one index (#92).
- `myc` is installed from crates.io; the unpublished Docker image is no longer advertised (#72, #73).
- Release builds reserve 8 KiB of stack per syntax-tree level for deep files instead of 32 KiB (~79 MiB instead of ~315 MiB of address space per worker at the 10,000-level limit) (#159). A new CI workflow (`stack-probe.yml`) measures the smallest stack each language's extraction survives on deeply nested input, in debug and release on Linux and macOS: the worst is ~1 KiB per level optimized and ~11.9 KiB unoptimized (debug keeps 32 KiB). The job writes the table to its summary and fails if either value drops below twice the worst measurement.
- The model cache defaults to `models/` in the data directory (`~/.myceliums/models`) instead of `.fastembed_cache/` in the working directory, so every `myc` invocation shares one copy (#157); `FASTEMBED_CACHE_DIR` and `HF_HOME` still override it. Old `.fastembed_cache/` directories can be deleted.

### Fixed
- Vector search no longer returns symbols that have no vector (#157): their placeholder was a zero vector, which scored cosine 0.5 and filled semantic and hybrid results of a partially embedded index; it is null now, which the search skips.
- Model files are downloaded by myceliums itself (ureq with native-tls, as hf-hub used; #157): over HTTPS only, redirects included (a redirect to plain HTTP fails); never past the pinned size (more bytes abort the download and remove them); a partial download is resumed only when the server answers with exactly the range asked for, else it starts over; the file is synced before it is renamed into place; and a PID lock per file (`<file>.part.lock`) keeps two processes from writing one partial file — the second waits and uses what the first downloaded. A stopped download keeps its partial file, and the progress is reported.
- Tokenizing for a local model holds a bounded amount of memory (#157): texts are tokenized and embedded in slices of 4,096 (the tokenizer sees 256 at a time), a text longer than the window is cut at the end of the first word past the window plus a 16-token margin before it is tokenized — the kept ids are those of the whole text, checked against all eight registry tokenizers — and only ids and type ids are kept. Tokenizing 20,000 texts of 8 KB with the default model's tokenizer raised peak memory by 3.2 GB at once and by 0.18 GB in groups (`tokenizing_a_large_corpus_*`, ignored tests). `EmbedStats::truncated_texts` counts the texts the window cut, not every text that fills it.
- Loading a model no longer holds the model cache's lock: a first load (and download) runs on the blocking pool, and lookups of other or already loaded models do not wait for it (#157).
- `myc analyze` re-analyzes an index whose vectors come from another embedding model, template or chunking than the project now configures, instead of reporting "Using cached analysis" until `--force` (#157).
- Incremental runs keep embedding with the index's own template when this build still produces it, instead of refusing every index built by an earlier template (#157); only an unknown or unrecorded template is refused, as before.
- `jina-embeddings-v2-base-code` claimed an 8,192-token budget but was always cut at 512 tokens by fastembed's default; every registry model now declares the 512-token window it embeds with (#157).
- Correctness follow-ups (#118): a Cypher query with an unterminated string, an unknown character or an integer out of range fails with the position (`Invalid query: unterminated string literal (no closing ') at position 26`) instead of being cut short silently (a trailing `;` is accepted); the Cypher guide and `myc query` examples used labels the executor rejects (`Function`, `Class`, `Community`) and now use `CodeSymbol`/`File` with `WHERE s.kind = ...`, checked by a test; incremental re-indexing (`myc analyze --watch`, `Analyzer::analyze_files`) applies the size, line-length, minified and binary skip rules of a full analysis; `myc analyze` and the MCP `analyze` tool report the files they skipped and why; a TypeScript `export { Bar as Foo }` no longer shadows an imported `Foo` inside its module; a `myc setup-claude` block that pushes CLAUDE.md past `max_file_size_kb` makes the index stale; a read of a registered repository whose index is missing says to run `myc analyze` (CLI) or is an `isError` result (MCP), and `analyze` rebuilds such a repository instead of answering from the cache; `StorageError` no longer prints the wrapped error twice in a chain and keeps nested contexts; `Store::open_existing` removes the empty directory LanceDB's `connect` creates when the index disappears during the call (Unix).
- Files written by `myc setup-claude` after `myc analyze` no longer make the index look stale (#151). Freshness — the MCP `Index:` line, the `analyze` tool's re-index decision and the non-git cache check — counts only files the analysis would index, through one predicate shared with the analyzer's file walk (`myceliums_core::index_scope::IndexScope`: hidden and build directories, known extensions, `include`/`exclude`/`skip_patterns`, size limit), plus `.myceliums.toml`. `.mcp.json` and `.claude/` therefore never count, and the routing block in CLAUDE.md / AGENTS.md is left out of the index (Markdown/MDX only; elsewhere the markers are plain text), so a Markdown file whose text outside the block is what the analysis indexed — compared with a fingerprint recorded at index time, or else with the committed version — is no change. An indexed file that grew past the size limit counts as changed. Before, the MCP `analyze` tool re-indexed after `setup-claude`; in the #125 runs that once ran into the client's 300 s timeout.
- A full re-analysis no longer drops existing embeddings (#151). Symbols whose embedding text is unchanged take their vector over from the index being replaced (same model, current vector geometry and embedding-text template only), so `skip_embeddings` / `--skip-embeddings` / the `myc session` default and a model that fails to load or embed leave only new or changed symbols without a vector; before, such a run replaced an embedded index with one without vectors (seen in #125 when an agent called `analyze` with `skip_embeddings`). A re-index with embeddings now embeds only the changed symbols. `analyze` says how many vectors were kept and warns when symbols have no vector because embedding was skipped, and a cached answer for an index built without embeddings reports `0/N` instead of `N/N`.
- The SessionStart hook's output now reaches the model, and session start no longer waits for an analysis (#152). `myc session . --yes` prints one JSON object whose `hookSpecificOutput.additionalContext` adds a single line of at most 280 characters (about 60 tokens) to the session. The line holds the repository id, the index state and `find_callers` / `impact_of_change` / `search_code` for structural questions. The index state is the freshness from the same check `myc callers` uses, or "stale, re-indexing in the background", "no index yet, building in the background" or "already running". Before, the status was only a `systemMessage`, shown to the user and not to the model; that status line stays, and also goes to stderr. A missing or stale index used to be re-analyzed in the foreground for up to 300 s. Claude Code waits for SessionStart hooks, so the first response waited too, and `myc analyze` printed its report onto the hook's stdout, where Claude Code would have added it to the model's context as plain text. The hook now starts a detached `myc analyze` in its own session (`setsid`), with output appended to `<data dir>/logs/session-<repo id>.log`, and returns at once (0.05 to 0.11 s on flask, debug build). The analysis takes the #98 lock that MCP `analyze` uses; while it is held the hook starts nothing and reports "already running". `--timeout` is now ignored. Skips and errors add no context and still exit 0. `myc setup-claude` gives the handler `"timeout": 15`; the command is unchanged.
- Opening a store or team store at a path that is not valid UTF-8 returns `StorageError::NonUtf8Path` instead of panicking (#101).
- Reading a registered repository whose index is missing (never built, deleted, or mid-swap during a rebuild) no longer creates an empty database and answers with zero counts: CLI read commands fail with `no index at <path>` and the dashboard answers 404 (#101).
- The `myc serve` API answers every failure with a status and `{"error", "next"}` instead of a `404` with an empty body (#118): an unknown `repo_id` is a `404` listing the registered ids, a registered repository without an index a `404` naming `myc analyze <path>`, an index replaced mid-request a `503` with `Retry-After`, semantic search on an index without embeddings a `409`, and a storage or computation failure a `500` with the cause. A table that fails to load fails the request instead of being served as empty (partial graphs, zero counts). The dashboard shows the message instead of an empty graph.
- `myc diff` compares with the previous analysis, chosen like the MCP drift tool (`myceliums_core::previous_snapshot`), instead of the latest snapshot, which was the current analysis itself (#97).
- Graph diffs never worked: every analysis overwrote the only snapshot, keyed by symbol uids that each analysis generates anew, and nothing wrote the versioned snapshots `snapshot_diff` compared. Each analysis now records a versioned snapshot (the newest 10 are kept) keyed by file, qualified name and kind, and `detect_architecture_drift` compares the previous analysis with the current graph by default (#97).
- The Claude Code PostToolUse hook read tool results as `{"text": ...}` JSON and their first line, which since #96 is the `Index:` line; it now reads plain text, skips the freshness line, and knows the new tool names (#97).
- Cypher `GROUP BY` on a property (`RETURN s.kind, count(s)`) grouped every row under `null`, and groups came out in a different order on every run; they are now keyed by the evaluated property and keep first-seen order (#96).
- The MCP `detect_impact` and `rename_symbol` outputs listed only affected files and `Rename: ? -> …` because they read JSON keys that do not exist; they now render the changed and affected symbols and each edit (#96).
- The PostToolUse hook that `myc setup-claude` installs now matches myceliums tools: Claude Code compares a matcher of only letters and `_` as an exact tool name, so the old `mcp__myceliums__` matched nothing; it is now `mcp__myceliums__.*` (#126).
- `myc setup-claude` refuses to rewrite a settings or MCP config file it cannot parse instead of replacing it with its own content (#126).
- `--strict-embeddings` is honored in the session bootstrap path (#69).
- The `embeddings` feature gate lost in #43 is restored (#70).
- Benchmark baselines are content-addressed instead of tied to a git commit (#86).
- Lint findings in test code, now that clippy covers `--all-targets` (#81–#85, #87).
- Hybrid search returns tied results in a fixed order instead of a per-process random one (#92).
- The manual benchmarks workflow no longer hides failing benches behind `continue-on-error` (#92).
