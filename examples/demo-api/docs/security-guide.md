# API Security Guide

## Password Handling

The `hash_password` function in `auth.py` is responsible for all password hashing.
It currently uses SHA256 with a configurable salt. For production deployments,
this should be replaced with argon2 or bcrypt.

The `verify_password` function compares a plaintext password against a stored hash
by calling `hash_password` internally. During migration periods, it also checks
legacy hash formats for backward compatibility.

## Token Management

JWT tokens are generated by `generate_jwt_token` with a configurable expiration.
Token verification happens in `verify_jwt_token`, which checks both signature
validity and expiration timestamps.

The `get_user_from_token` function extracts the user ID from a verified token
and loads the corresponding user record from the database via `get_user`.

## Middleware

The `require_auth` decorator should be applied to all endpoints that need
authentication. It calls `verify_jwt_token` and attaches the user to the
request context.

For admin-only endpoints, use `require_admin` which extends `require_auth`
with an additional role check.

## User Registration

New users are created through the `register` endpoint which:
1. Validates input via `validate_json`
2. Checks for existing users via `get_user_by_username` and `get_user_by_email`
3. Hashes the password with `hash_password`
4. Stores the user via `create_user`
